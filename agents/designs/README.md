# Design documents

Create a design document only when a todo item needs enough detail that keeping it inline would make the planning files noisy.

Rules:

- Prefer no design doc for straightforward work.
- Link the design from the relevant `todo.md` item.
- Capture decisions, constraints and acceptance details; avoid implementation diaries.
- Keep product scope in `requirements.md`, not in design documents.
- Once obsolete, mark a design historical rather than letting it silently override current requirements.
