# Visamp Requirements

Visamp helps musicians create, license, produce and distribute visual content for music releases.

Requirements describe product capabilities, not implementation tasks. Check an item only when the capability is verified.

## Identity and content
- [ ] **R001** A user can act as a music artist, visual creator, or both.
- [ ] **R002** Artists can upload and manage music tracks.
- [ ] **R003** Tracks can be played through the Visamp visual engine.
- [ ] **R004** Visamp can analyse a track for audio-reactive and content-generation purposes.

## Visual creators
- [ ] **R010** Creators can create and save visualisations with a distribution class: private, public, protected or product.
- [ ] **R011** Visript supports creator-defined `param` declarations with an initial value.
- [ ] **R012** Creator-defined params are readable by Visript but writable only by the host/Studio.
- [ ] **R013** The engine exposes standard host-provided params for music/video context in addition to creator-defined params.
- [ ] **R014** Creators retain attribution for distributed visualisations.
- [ ] **R015** Product visualisations can set a credit price and are customisable only through params.
- [ ] **R016** Creators can view earnings generated by licensed product use.
- [ ] **R017** Public visualisations are source-visible, forkable and free for commercial video use.
- [ ] **R018** Protected visualisations are usable like public visualisations but are not source-visible or forkable.

## Visual marketplace
- [ ] **R020** Artists can browse public, protected and product visualisations available for video creation.
- [ ] **R021** Artists can preview eligible visualisations against their own music.
- [ ] **R022** Artists can modify a visualisation only through its params when that distribution class requires it.
- [ ] **R023** Product visualisations can be licensed using Visamp credits.
- [ ] **R024** A product licence grants defined promotional use with the licensed track/video.
- [ ] **R025** Product revenue is split between the visual creator and Visamp.
- [ ] **R026** Distribution, source visibility, forkability, licensing and attribution rules are enforced below the UI layer.

## Studio and video creation
- [ ] **R030** Studio provides a My Videos workspace and a Video Maker workspace.
- [ ] **R031** My Videos lists an artist's videos and supports create, open/edit and preview.
- [ ] **R032** My Videos shows current distribution and scheduling state for each video.
- [ ] **R033** Video Maker uses only music controlled by the signed-in artist.
- [ ] **R034** Video Maker offers only visualisations whose distribution class permits video use.
- [ ] **R035** Video Maker provides a timeline-based authoring experience derived from the existing set builder.
- [ ] **R036** Artists can change visual params while authoring a video.
- [ ] **R037** Product visuals require a valid licence before final export/distribution.
- [ ] **R038** Visamp can render/export common social-video aspect ratios and durations.
- [ ] **R039** Generated videos retain track, visualisation, creator, param and licensing provenance.

## Releases and campaigns
- [ ] **R040** Artists can create a release containing one or more tracks.
- [ ] **R041** Artists can create a campaign for a release.
- [ ] **R042** Campaigns can contain multiple generated content assets.
- [ ] **R043** Campaign content can be scheduled for publication.
- [ ] **R044** Artists can connect supported social accounts.
- [ ] **R045** Visamp can publish scheduled content where platform APIs permit.
- [ ] **R046** Campaign performance can be measured where platform APIs provide the data.

## Credits and commerce
- [ ] **R050** Users can purchase Visamp credits.
- [ ] **R051** Chargeable actions show their credit price before commitment.
- [ ] **R052** Users can enable automatic credit top-up.
- [ ] **R053** Credit transactions are recorded in an auditable ledger.
- [ ] **R054** Creator earnings are recorded independently from spendable user credits.
- [ ] **R055** Failed chargeable operations do not consume credits unless value was delivered.
- [ ] **R056** Creator earnings can ultimately be paid out under defined marketplace terms.

## Visamp network
- [ ] **R060** Artists can publish eligible music/video content publicly on Visamp.
- [ ] **R061** Visamp provides public artist pages.
- [ ] **R062** Visamp provides public visual-creator pages.
- [ ] **R063** Visitors can discover published music and visual content.
- [ ] **R064** Published content attributes both the music artist and visual creator.
- [ ] **R065** Visamp can curate and feature selected artists, creators and releases.

## Platform architecture
- [ ] **R070** Core product capabilities are implemented independently of the web UI.
- [ ] **R071** Core capabilities can be exposed programmatically through APIs and MCP.
- [ ] **R072** Authentication, permissions, licensing and charging are enforced at the service boundary.
- [ ] **R073** Significant product actions are measurable for product validation.
- [ ] **R074** The same underlying capabilities can serve the web app and future agent/integration clients.

## Prototype validation
These are the immediate requirements for the first testable Studio/marketplace prototype.

- [ ] **R090** Studio has My Videos and Video Maker tabs.
- [ ] **R091** Video Maker can pair an owned track with an eligible visualisation.
- [ ] **R092** A product visual's declared params are editable live without source access.
- [ ] **R093** A musician can spend credits to license a product visual and the creator receives an earnings record.
- [ ] **R094** The authored pairing can produce a usable promotional video which appears in My Videos.
